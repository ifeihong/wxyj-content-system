# 视频连续性、去重与交付验收

## 先确定一条完整叙事

同一产品在不同镜头出现是身份连续；相同观察面、景别、主体占比和信息再次出现才是重复。默认全片逐对检查，不只检查相邻镜头。用户明确要求全片不重复时，不使用“半开礼盒最多两镜”的旧额度。不能靠修改镜头名、转场、字幕或背景颜色判定为新画面。

先写一句观众能理解的事件，再分配镜头。每镜登记主体观察区域、真实机位、景别、产品状态、唯一信息、承接理由和对应旁白。先完成叙事，再按动作需求决定Seedance或静态图，不先套固定的3静态+2视频比例。

逐对检查两个问题：画面是否实质重复；删去本镜是否丢失信息或事件。若只是为了去重加入无关背面标签、风味静物或故事文字，退回策划。处于“只看一眼”的幽默主题时，笑点必须在结尾兑现，不在中段变回常规参数介绍。30年、桶型、酒精度和品鉴词可自然存在于标签，但无需每条旁白重讲。

## 状态和转场

- 同一场景固定桌面、背景、色温、主光方向与产品身份；允许景别和机位有意变化。
- 登记每镜 `state_in`、`state_out`。闭盒变开盒、瓶在盒内变桌上、盒盖再次合上必须有动作、合理省略或明确的时间跳转，记录在下一镜 `bridge_from_previous`。
- 静态图不能承担持续开盒动作。旁白说“打开”时若仍显示闭合背面，需要改画面或改台词。
- 转场跟随木框边缘、视线、焦点或动作；不强制每个过场完全不同。明确要求不同效果时，也必须满足方向、色彩和事件连续，不凭空把皮革内页做成可翻纸页。

## 一个可追踪的生产依据

`video-master/production-plan.json` 是本次镜头顺序、源资产、参考图角色和交付版本的依据。用模板创建，填充原文件，不在已有JSON/YAML末尾追加第二份对象。

每次修改主体、角度、旁白或图像，增加 `revision`，同步分镜表、任务卡、TXT提示词、运动计划、发布文案和最终链接。每个实际交付文件在 `documents` 登记路径、SHA-256及对应revision；内容变化后旧校验失效。未变化且仍适配的图片可保留，改动资产另存版本，旧候选保留在非交付区。文件名写实际内容，不用open-box命名闭盒成图。

外部镜头的首帧必须是Agent生成的同场景图，图库原图不能冒充已生成首帧。首帧模式只向首帧槽上传这一张；产品图、尺寸图仅在平台支持辅助参考时上传，否则作为Agent生图和QA依据。需要多参考模式时在任务卡说明，不能写first-frame却要求把四张原图都当首帧。生成时长和剪辑使用时长分别登记；平台不支持3.5秒时使用其可选时长覆盖镜头及剪辑余量，不能声称各平台参数完全一致。

用户只负责外部视频生成与回传；Agent负责静态成图、Seedance首帧、参考图副本与提示词；ChatCut负责可编辑剪辑。复制提示词只包含产品、场景和运动。简短负向约束可说“无新增文字或图形”，不要把后期工具、音乐、字幕排版或长串时间线设计写进任一可复制TXT。原有标签必须保留，不误写成“无文字”。

## 三种验证结论

1. `draft`：结构可读，字段尚可待填；不能说制作包可执行或图片通过QA。
2. `ready`：每个静态图/Seedance首帧实际存在、画幅合规、参考图存在、版本/hash一致；逐图几何报告及全片接触表审阅记录完整，人工已判断连续且不重复。此时可交付用户生成外部视频，仍不等于成片完成。
3. `publish`：在ready基础上，回传视频、实际时间线、渲染文件及视听验收完成后才进入发布状态。

执行 `python scripts/validate_video_production_plan.py <run-dir> --stage ready`。脚本能检查文件、尺寸、重复声明/重复文件、版本和审阅证据是否登记，不能理解画面语义、判定瓶型准确或确认音乐好听。人工必须打开实际图片/接触表，记录看到的具体特征与疑点。没有查看成图，禁止填写pass；测量不可见时写“无法核准”，不能补编数值。

原生比例与导出分辨率分开记录。默认视频9:16/1080×1920；用户当次明确3:4则整片按3:4，不套用默认禁止。941×1672不等于精确9:16，不能改标签称合格；裁切/拉伸不能作为原生校验通过依据。

## 返工顺序

先定位失败层：叙事、构图重复、几何、文字、运动、音频或交付。每次只修对应层；两次相同失败后，重新核对输入/母版与可见证据，再选低风险构图。请求完整生产包时，不把缺图改成“请用户按提示词生成”来结案。暂时缺少资产时如实保留draft并列缺口。

## production-plan填法

模板位于 `assets/templates/video-production-plan.json`。路径相对运行目录，参考原图需复制到包内。每个文件证据对象为 `{"path":"相对路径","sha256":"实际SHA-256小写值","revision":1}`；必须计算实际文件，不能照抄占位值。审阅对象还需 `status: pass`，其文件写明对应图像路径/哈希、观察结果及问题，不用空白验收表充数。

`shots` 按实际镜头顺序填，每镜包含：

| 字段 | 填写内容 |
| --- | --- |
| id / source_type | S01等唯一编号；static或seedance |
| subject_region / view / framing / visual_role | 主体部位、真实机位、景别、唯一信息；不能仅改role掩盖重复 |
| state_in / state_out | 开合、瓶位、朝向；前后有变化时下一镜说明state_change_reason |
| bridge_from_previous | 从上一镜切到本镜的视觉/语义理由（首镜可省略） |
| narration / visual_support | 对应台词及当前画面如何承接；无旁白方案明确写“无旁白”及画面信息，不虚构配音 |
| edit_duration_seconds / full_bottle | 剪辑中有效持续秒数；是否出现完整瓶身true/false |
| image / review | Agent实际成图的证据对象、该图人工审阅证据 |
| references | 文件证据对象数组，各加role；整瓶至少geometry_master与dimension_check，按主Skill补齐角度/酒标/结构 |
| external | 仅seedance需要：见下方 |

external默认填写 `input_mode: first-frame`、`first_frame`（与image.path相同）、`generation_duration_seconds`、`output_name`（含s01等镜号的mp4名），以及positive、negative、combined、task_card四个文件证据对象。默认 `playback_speed: 1`，显式减速可为0.5；生成时长/速度须覆盖剪辑时间，实际运动质量另检。first-last-frame还要last_frame文件证据且同画幅；reference-guided/text-to-video需mode_reason，不填首尾帧槽。text-to-video不可承担完整酒瓶还原；image仍登记本镜已生成的构图预览用于全片审阅，不冒充实际模型输入。

静态镜头填写`requested_motion`记录当次确认的motion_pattern/start_scale/end_scale，平移另填起止位置；publish时与motion-plan逐镜比对。首次生成任务包仅pending-qa；安全更新与成片验收登记见`docs/reliability-v3.4.1.md`。

`documents` 登记storyboard.md、edit-plan.md、motion-plan.json及其他实际交付文档的证据；`sequence_review`登记全片接触表人工评审文件。更新revision后所有仍引用文件需重核适配性并登记当前revision，不代表必须重新生成未变图片。脚本只查哈希/版本和字段，TXT与任务卡语义是否相同仍须逐项核对。
