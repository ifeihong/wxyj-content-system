# 数据驱动提示与实验系统

## 使用时机

每次确定新母题前，先读取近期 `performance-log.csv`，再创建或更新当前运行包的 `performance-brief.json`。该文件是下一条内容的内部策划依据，不进入成图、成片或公开文案。

```powershell
python scripts/analyze_performance.py `
  <运营内容库>/performance-log.csv `
  --date YYYY-MM-DD `
  --theme-family <theme-family> `
  --output <运行目录>/performance-brief.json
```

## 数据成熟度

- 发布后少于 48 小时，或缺少发布后小时数：标为 `observation`；允许记录，但不能生成硬性内容结论。
- 已满 48 小时：标为成熟数据，参与下次内容的提示建议。
- 少于 10 条成熟且可比较的内容：`baseline_status` 为 `hypothesis`；只测试假设，不淘汰栏目、不固化公式。
- 满 10 条成熟可比内容：才允许用中位数建立 `established` 基线。

导出时保留平台原始字段，尤其是封面点击、2秒跳出、5秒完播、平均观看、完成、主页访问与关注。不要用不同平台的同名指标强行横向比较。

## 主题冷却

当同一 `theme_family` 在最近 7 天内已有两条成熟内容时，`performance-brief.json` 发出冷却提示：下一条默认改用不同主主题。

冷却不是发布禁令。若该主题属于有明确目标的活动，可填写 `creative-record.json` 的 `campaign_override`，并同时改变下列三项中的至少两项：

1. 用户问题；
2. 首屏/首图形式；
3. 主事实组合。

创意台账仍负责 30 天创意指纹和 14 天视觉配方的硬去重；效果台账只负责“近期受众是否已看腻”和“下一条该测试什么”。

## 单变量实验卡

每个 v2.7.0 新运行包都在 `creative-record.json` 中填写：

| 字段 | 规则 | 示例 |
| --- | --- | --- |
| `variable` | 只选一个可观察变量 | `first-second-product-reveal` |
| `hypothesis` | 描述预期因果，不写结论 | 完整产品与可见动作可降低前2秒跳出 |
| `success_metric` | 使用所在平台真实字段 | `two_second_bounce_rate` |
| `baseline` | 写成熟中位数或 `not-established` | `recent mature douyin median` |
| `result` | 发布前为 `pending`，成熟后再填写 | `pending` |

发布候选必须填 `variable`、`hypothesis` 和 `success_metric`。不允许同一条内容同时把标题、时长、封面、首秒、旁白和 CTA 都改掉，否则无法复盘。

## 平台提示规则

### 抖音与视频号

- 0.0–0.8 秒：先出现完整、准确的产品主体、酒标局部或礼盒结构，并发生一个可见动作；不使用纯文字、黑底或静态片头。
- 2.0–5.0 秒：兑现标题承诺，再解释日期、桶型、风味或包装。
- 一条视频只承担一个核心承诺。日期、桶号、风味、礼盒不可同时作为并列主线。
- 数据出现前段跳出问题时，优先测试 `first-second-product-reveal`；不要先归因给音乐、旁白音色或平台流量。
- 15–22 秒是可选测试区间，不是默认强制时长；必须记录真实成片时长后再比较。

### 小红书

- 封面只承担一个好奇钩子；第 2 页立即给出具体产品判断或可保存信息，且不得重复封面标题。
- 封面点击高、浏览后互动低时，保留钩子而重写第 2 页和内页价值，不要急着重做整套视觉。
- 冷启动互动优先感官、礼赠或场景选择；年份、桶型、桶号等技术问题只在教育型内容中使用。
- 首评承担低门槛互动或栏目承诺，不把复杂问题压到正文最后一行。

## 复盘输出

每次复盘先输出以下内部简报，再生成下一条提示词：

1. 成熟数据与观察数据数量；
2. 本次不应重复的主题和视觉执行；
3. 本次唯一实验变量；
4. 平台首屏、页面承接或互动问题的具体要求；
5. 哪些结论仍只是样本假设。
