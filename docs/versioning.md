# 版本策略

## 当前版本

`2.2.2`

## Semantic Versioning

格式：

```text
MAJOR.MINOR.PATCH
```

### MAJOR

以下变化增加主版本：

- 修改 Skill ID；
- 修改内容运行目录；
- 删除平台发布字段；
- 修改脚本公开接口；
- 让旧内容包无法继续验证。

### MINOR

以下变化增加次版本：

- 新增平台；
- 新增兼容脚本；
- 新增内容模块或模板；
- 新增校验规则，但旧合法运行包仍然合法。

### PATCH

以下变化增加修订版本：

- 修正产品事实或文档；
- 修复脚本问题；
- 改善提示词、示例和错误信息；
- 收紧不影响正常内容的风险词。

## 更新流程

1. 写失败测试或复现记录；
2. 修改 Skill、脚本或文档；
3. 更新 `VERSION`；
4. 更新 `CHANGELOG.md`；
5. 运行单元测试和 Skill 校验；
6. 使用一个真实内容任务做前向验证；
7. 发布对应 Git Tag。

## 迁移

主版本升级必须在 CHANGELOG 中说明：

- 不兼容变化；
- 旧目录如何保留；
- 文件如何复制；
- 旧脚本是否兼容；
- 新调用名称。
